# 2026-08-11

## 调查：Antigravity IDE 模型映射/路由不生效

根因：模型路由依赖 `mitm.model_routing_enabled` 这个主开关，但它被**运行时缓存**：
- dylib（`AntigravityTun.cpp` 的 `my_connect`/`my_getaddrinfo`）用 `static` 只 `Load()` 一次配置，进程内不再重读 → 已运行的 IDE 不会感知 proxy_config.json 变更。
- Go 代理（`tools/mitm_proxy/main.go:101`）也只在启动时读一次该开关，passthrough 模式不会自动退出。
- UI 主开关（HomeView:806-815 / ProxySettingsView:143-156）只写 proxy_config.json，**不重启 Go 代理、也不重启目标 App**，故切开关对正在运行的 IDE 无效（HomeView 第 820/826 行有弱提示“需重新修复应用”）。

链路：my_getaddrinfo 解析 FakeIP → my_connect 命中 FakeIP 且 model_routing_enabled&&IsAppAllowedForMitm() 且域名在硬编码 5 域名名单内 → 重定向到 :18081 Go MITM 代理 → 按 model_routing.json 改写。

次要问题：dylib 的 MITM 域名名单硬编码（与 Go 代理 defaultMitmHosts/用户 mitm.hosts 脱节）；Config.hpp 默认值自相矛盾（成员 false vs 解析默认 true）。

详见 `docs/model_routing_investigation.md`。修复方向：dylib 运行时重载开关 + 域名名单配置化 + UI 切换时重启代理/App。
